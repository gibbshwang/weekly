# Design: Next.js Toss Billing Template

Generated by /brainstorm on 2026-04-12
Status: APPROVED

## Problem

Chat MBTI에서 구현한 Toss Payments 구독 결제 시스템을 다른 Next.js + Firebase 프로젝트(이혼 상담 AI 등)에서도 재사용하고 싶다. 매번 처음부터 구현하는 것은 비효율적이고 버그 재발 위험이 있다.

## Decisions

| # | 선택지 | 결정 | 이유 |
|---|--------|------|------|
| 1 | 모듈화 범위 | B: 서버 + UI 풀세트 | 두 프로젝트 스택 동일, UI 플로우도 동일 |
| 2 | 위치 | A: 독립 레포 | 버전 관리, 향후 npm 승격 가능 |
| 3 | 설정 방식 | C: config + env 하이브리드 | 비즈니스 로직은 config, 시크릿은 env |
| 4 | 결제 타입 | A: 구독(billingKey)만 | 검증된 코드만, 일회성은 나중에 |
| 5 | 구현 방식 | 1: 직접 추출 | 검증된 코드 그대로, 최소 수정 |

### 앱 의존성 분리 (Adapters)

Chat MBTI 고유 의존성 3가지를 어댑터 패턴으로 분리:

1. **adapters/auth.ts** — `authenticate(req) → uid | null` 함수. Firebase Auth 기본 구현 제공.
2. **adapters/db.ts** — `adminDb` export. Firestore Admin SDK 기본 구현 제공. import 경로만 프로젝트에 맞게 변경.
3. **UI 컴포넌트** — Modal, Button 등 앱 전용 컴포넌트를 기본 HTML + Tailwind로 대체. next-intl 의존성은 유지.

### 환경변수 (.env.example)

```
# Toss Payments (필수)
NEXT_PUBLIC_TOSS_CLIENT_KEY=test_ck_...
TOSS_SECRET_KEY=test_sk_...
CRON_SECRET=random-string

# Firebase (필수)
GOOGLE_APPLICATION_CREDENTIALS=path/to/serviceAccount.json

# 선택
WEBHOOK_SKIP_IP_CHECK=true  # 개발환경에서 IP 검증 스킵
```

## Testing

- 기존 12개 테스트 파일 포함 (~200 테스트)
- 하드코딩된 9900, 'Pro' 등을 billing.config 참조로 변경
- `npx vitest run`으로 실행

## Security (기존 유지)

- SEC-01: billingKey 클라이언트 미노출
- SEC-02: URL 파라미터 sanitization
- SEC-03: 웹훅 IP 화이트리스트
- SEC-04: 웹훅 멱등성
- SEC-05: Cron CRON_SECRET 검증

## 새 프로젝트 적용 순서 (SETUP.md)

1. 템플릿 파일을 프로젝트 src/에 복사
2. `billing.config.ts` 수정 (금액, 플랜명 등)
3. `adapters/auth.ts`에 프로젝트 인증 로직 연결
4. `adapters/db.ts`에 firebaseAdmin import 경로 설정
5. 환경변수 설정 (Toss 키, CRON_SECRET)
6. Firestore 보안 규칙에 billing, payments 컬렉션 추가
7. Cron 설정 (Firebase App Hosting 또는 Vercel)
8. `npx vitest run`으로 테스트 확인
9. 배포
