<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> linkWithPopup | Google OAuth popup initiated from browser |
| Client -> POST /api/sessions | Save request with session data + Bearer token |
| SaveConsentDialog -> save flow | PIPA consent gates the entire save process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Spoofing | linkWithPopup | mitigate | Use `linkWithPopup(auth.currentUser!, provider)` NOT `signInWithPopup` — preserves anonymous UID |
| T-04-08 | Tampering | SaveButton fetch body | mitigate | `userId` written server-side from verified token, not from request body |
| T-04-09 | Repudiation | PIPA consent bypass | mitigate | SaveConsentDialog is mandatory UI gate; `pipaConsentedAt` timestamp sent to server and stored in Firestore |
| T-04-10 | Information Disclosure | Google account email exposure | accept | linkWithPopup returns Google profile info; only UID is stored in Firestore, not email/name |
| T-04-11 | Denial of Service | Popup-blocked error loop | mitigate | Error message displayed with Korean text; button re-enabled on error for retry |
</threat_model>
